### 一、 系统整体架构概览

整体采用**配置与逻辑分离**的设计模式：
* **`src/config.py`**：负责环境变量加载、缺失配置校验（Fail-Fast 机制）以及系统级别 Prompt（人设与行为准则）的集中管理。
* **`src/client.py`**：负责 API 客户端初始化、多轮对话（Chat Session）管理以及针对高并发/网络抖动的**容错重试机制**（Resilience Pattern）。

```
[ .env 文件 ] ──> [ src/config.py ] ──(读取 Key & Prompt)──> [ src/client.py ]
                                                                 │
                                                       (调用 Google GenAI API)
                                                                 ▼
                                                        [ Gemini 模型服务 ]
```

---

### 二、 模块详细分析

#### 1. `src/config.py` — 配置与安全校验模块
* **环境变量管理**：通过 `python-dotenv` 库加载 `.env`，避免硬编码 API Key，符合 12-Factor App 的安全最佳实践。
* **快速失败机制（Fail-Fast）**：在模块加载阶段即对 `GEMINI_API_KEY` 进行非空检查。若缺失直接调用 `sys.exit(1)` 中止程序，防止后续运行时产生无效请求。
* **人设约束（System Instruction）**：定义了高约束度的系统提示词，限定了 AI 的专业度、Markdown/LaTeX 格式规范以及多语言（中/英/德）支持能力。

#### 2. `src/client.py` — 客户端与容错控制模块
* **采用最新的 SDK**：使用了全新的 `google.genai` SDK（而非旧版的 `google.generativeai`），基于 `genai.Client` 进行实例化。
* **低随机性参数配置**：设置 `temperature=0.3`，降低生成内容的随机性，符合科研/代码开发场景对**确定性与严谨性**的要求。
* **容错与重试机制（Fault Tolerance）**：
  * 实现 `send_message_with_retry` 方法，针对 HTTP `503 Unavailable` 或服务器繁忙等临时性错误（Transient Faults）进行拦截。
  * 采用**线性/递增退避策略**（Wait Time $t = \text{attempt} \times 2$ 秒），避免在服务端过载时进行高频无效请求。
  * 引入 `rich` 库（通过传入的 `console` 对象）提供交互友好、带有色彩和格式的终端错误提示。

---

### 三、 关键设计亮点

1. **职责分离（Decoupling）**：API 配置、人设 Prompt 与 API 请求逻辑完全解耦，易于后续扩展（如更换模型或动态修改 Prompt）。
2. **健壮的网络抗性**：针对大模型 API 常见的 503 过载问题，内置了开箱即用的重试逻辑，提升了 CLI 工具的可用性。
3. **高质量上下文控制**：使用 `client.chats.create` 创建带状态的会话，自动管理多轮对话历史，同时在 Session 级别绑定 `system_instruction`。

### 四、 潜在风险与优化建议

| 问题维度 | 当前实现分析 | 优化建议 |
| :--- | :--- | :--- |
| **模型名称** | 使用了非标准/假设的模型名 `gemini-3.6-flash` | 建议将模型名称抽取至 `config.py` 作为配置项，或修正为标准模型名称（如 `gemini-2.0-flash` 或 `gemini-1.5-pro`）。 |
| **异常匹配机制** | 使用字符串包含匹配 `if "503" in error_str` 捕获异常 | 较为脆弱。建议优先捕获 `google.genai.errors.APIError` 类型的结构化异常代码（Status Code）。 |
| **退避算法** | 当前为线性退避 ($2, 4, 6\dots$) | 面对严重的 503 拥堵，建议改用**带抖动的指数退避**（Exponential Backoff with Jitter），公式：$T_{wait} = 2^{\text{attempt}} + \text{random\_jitter}$。 |
| **类型提示 (Type Hints)** | 缺少入参及返回值类型声明 | 可增加 `from rich.console import Console` 进行类型标注，提升 IDE 补全与代码可维护性。 |

### 五、 推荐重构方案（部分示例）

#### 优化后的 `src/client.py` 容错逻辑片段：

```python
import time
import random
from google import genai
from google.genai import types
from google.genai.errors import APIError
from src.config import API_KEY, SYSTEM_INSTRUCTION, MODEL_NAME

class GeminiAssistant:
    def __init__(self, console):
        self.console = console
        self.client = genai.Client(api_key=API_KEY)
        self.chat = self.client.chats.create(
            model=MODEL_NAME,
            config=types.GenerateContentConfig(
                system_instruction=SYSTEM_INSTRUCTION,
                temperature=0.3,
            )
        )

    def send_message_with_retry(self, prompt: str, max_retries: int = 3):
        """带有指数退避+随机抖动自动重试机制的消息发送方法"""
        for attempt in range(1, max_retries + 1):
            try:
                return self.chat.send_message(prompt)
            except Exception as e:
                error_str = str(e)
                # 匹配常见服务不可用错误
                if any(code in error_str for code in ["503", "UNAVAILABLE", "high demand"]):
                    if attempt < max_retries:
                        # 指数退避 + 随机抖动 (Full Jitter)
                        wait_time = (2 ** attempt) + random.uniform(0, 1)
                        self.console.print(
                            f"[bold yellow]⚠️ 服务器繁忙 (503)，正在重试 ({attempt}/{max_retries})，"
                            f"等待 {wait_time:.1f} 秒...[/bold yellow]"
                        )
                        time.sleep(wait_time)
                        continue
                raise e
```
