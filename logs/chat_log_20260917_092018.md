# 📐 架构概览与设计模式

本项目是一个基于 **Google Gemini API** 的命令行科研与代码分析助手，采用了标准的**模块化分层架构**：

```
[ 用户终端 (CLI) ]
       │
       ▼
[ main.py (交互控制层) ] ───► [ logger.py (日志归档) ]
       │
       ├──► [ file_parser.py (文件/目录上下文解析) ]
       │
       └──► [ client.py (API 客户端 & 重试机制) ] ───► [ config.py (全局配置) ]
```

### 核心职责划分：
1. **配置层 (`config.py`)**: 环境变量加载、API Key 校验及系统级 Prompt 管理。
2. **通信层 (`client.py`)**: 封装 Gemini SDK，内置指数退避（Exponential Backoff）重试策略。
3. **解析层 (`file_parser.py`)**: 静态工具类，负责单/多文件提取及递归目录扫描。
4. **持久层 (`logger.py`)**: 实时追加生成 Markdown 格式的本地对话日志。
5. **交互层 (`main.py`)**: 基于 `rich` 库构建终端 UI，处理快捷指令及主循环逻辑。

---

# 🌟 优秀设计亮点

1. **鲁棒的重试策略（`client.py`）**：
   引入对 `503 Service Unavailable` 或高负载场景的自动捕获与线性/退避重试，退避时间公式为：
   $$T_{\text{wait}}(a) = 2 \times a \quad (a \text{ 为当前重试次数})$$
   极大地提升了 CLI 在高并发或网络波动时的稳定性。

2. **优秀的 Prompt 上下文工程（`file_parser.py`）**：
   在 `scan_directory` 中不仅遍历文件，还构筑了可视化的目录树结构（Tree Topology），配合 Markdown 代码块封装，使 LLM 能精准感知全局架构与代码依赖。

3. **优雅的终端 UI 体验（`main.py`）**：
   利用 `rich` 库的 `Panel`、`Table` 和 `Markdown` 渲染，提升了交互可读性，指令路由简单明确。

# 🔍 潜在隐患与改进建议 (Code Review)

### 1. 🐛 **重大 Bug：日志记录上下文缺失**
* **位置**：`src/main.py` 第 148 行
* **问题**：在执行 `/read` 或 `/scan` 后，传递给日志记录器的是原始指令字符串（如 `/scan src/`），而非实际发送给 AI 的拼接 Prompt (`prompt_to_send`)。
```python
# 当前代码：
logger.log_interaction(user_input, response.text)

# 建议修正：
logger.log_interaction(prompt_to_send, response.text)
```
* **影响**：查阅本地 `.md` 日志时，无法追溯当时发送给 AI 的具体代码上下文。

---

### 2. ⚙️ **配置硬编码与模型名称问题**
* **位置**：`src/client.py` 第 11 行
* **问题**：模型名称硬编码为 `"gemini-3.6-flash"`（目前 Gemini 官方主打版本为 `gemini-1.5-flash` 或 `gemini-2.0-flash-exp`）。此外，重试参数、温度系数等硬编码在类中。
* **建议**：提升配置可扩展性，将模型名称与参数提取至 `config.py` 或 `.env` 中：
```python
# config.py
MODEL_NAME = os.getenv("GEMINI_MODEL", "gemini-2.0-flash-exp")
TEMPERATURE = float(os.getenv("TEMPERATURE", "0.3"))
MAX_RETRIES = int(os.getenv("MAX_RETRIES", "3"))
```

---

### 3. 🚨 **大项目上下文溢出风险 (Token Limit)**
* **位置**：`src/file_parser.py` 中的 `scan_directory`
* **问题**：如果用户执行 `/scan .` 扫描大型项目，没有任何**文件大小限制**或**总 Token 截断机制**，可能导致单次请求的 Prompt 过大，引发 API 超时或消耗大量配额。
* **建议**：在 `scan_directory` 中增加单文件大小阈值判断（如 $> 100\text{KB}$ 跳过），或增加总字符数限制告警。

---

### 4. 🐍 **Python 代码规范与类型提示（Type Hints）**
* **问题**：全栈函数缺乏 Python 官方推荐的类型标注（Type Hints），降低了 IDE 的补全体验与静态代码检查（如 `mypy`）的效果。
